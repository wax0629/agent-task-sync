# Agent Task Sync 原型规格（v0.2）

日期：2026-09-02  
原型目标：验证“Agent 对话创建任务 -> checkpoint -> GitHub 同步 -> 换设备/换 Agent 无缝继续”的核心闭环。

## 1. 原型范围

本轮做一个中保真、可点击的 Web 原型，覆盖多个项目入口、一个项目内的任务列表、任务详情、完整任务接续信息、handoff、同步和冲突处理。

不做登录、真实 GitHub OAuth、真实 Agent Hook 和生产级数据库。交互使用模拟数据，但流程必须与未来产品一致。

## 2. 设计方向

### 产品 register

这是一个工具型工作台，不是营销页面。用户处于专注、快速交接和排查状态，界面应支持扫描、比较和决策。

### 视觉策略

- Restrained：白色内容区、深色文字、低饱和中性色
- 使用单一主色表达“当前动作/同步”，使用少量第二强调色表达“阻塞/待审阅”
- 不使用装饰性渐变、漂浮光球或大面积卡片堆叠
- 采用系统无衬线字体，固定字号层级，优先信息密度和可读性
- 主色可基于 `oklch(0.470 0.173 354.8)` 调整为较深的红莓色；背景使用纯白，避免暖米色 SaaS 风格

### 信息层级

```text
任务目标和当前状态 > 最近完成和下一步 > 决策/问题/验证 > Agent/设备状态 > 活动历史 > 原始事件细节
```

## 3. 信息架构

```text
App Shell
├── 项目列表（多个 GitHub 仓库）
├── 项目任务列表
│   ├── 全部任务
│   ├── 正在进行
│   ├── 待接手
│   ├── 被阻塞
│   └── 待处理冲突
├── 任务详情：接续主视图
│   ├── 任务计划
│   ├── 工作记录
│   ├── Handoff
│   └── 同步与冲突
├── Agent 侧恢复面板
└── 设置（原型中隐藏）
```

### 页面职责

| 页面 | 用户要回答的问题 | 页面不承担的职责 |
|---|---|---|
| 项目列表 | 我有哪些项目，哪个项目需要继续？ | 不展示任务级长篇上下文 |
| 项目任务列表 | 这个项目有哪些任务，哪个任务现在最值得处理？ | 不展示完整事件流 |
| 任务接续主视图 | 任务目标是什么，现在做到哪里，下一步是什么？ | 不要求用户阅读 JSONL |
| Agent 恢复面板 | Agent 是否读到了同一份上下文，能否继续工作？ | 不自动把普通聊天全部存档 |
| 同步/冲突视图 | 本地和远程有什么差异，需要我做什么决定？ | 不替用户静默解决语义冲突 |

## 4. 首屏：项目列表

### 目标

让用户在 5 秒内知道：有哪些 GitHub 项目、哪个项目最近有进展、哪个项目需要继续处理。

### 布局

```text
┌─────────────────────────────────────────────────────────────┐
│ Agent Task Sync                         [同步] [新建项目]    │
├──────────────┬──────────────────────────────────────────────┤
│ 我的项目      │ 搜索项目...                                  │
│               ├──────────────────────────────────────────────┤
│ 所有项目      │ ┌────────────────────┐ ┌────────────────────┐ │
│ 最近打开      │ │ Agent Task Sync     │ │ Kaneo MCP Bridge    │ │
│               │ │ 3 个活跃任务        │ │ 已同步              │ │
│               │ │ 最近更新 12 分钟前   │ │ 最近更新 昨天       │ │
│               │ │ [进入项目]          │ │ [进入项目]          │ │
│               │ └────────────────────┘ └────────────────────┘ │
└──────────────┴──────────────────────────────────────────────┘
```

项目卡片的主信息是仓库和项目健康状态，不是 Agent 或设备。Agent/设备只在项目有活动、未同步或冲突时作为辅助标识出现。

## 4.1 项目任务列表

进入项目后展示任务流，但采用状态分组列表，而不是大面积 Kanban：

```text
Agent Task Sync   github.com/.../agent-task-sync      [同步：本地领先 2]
目标：同步多个 Agent 在不同设备上的任务上下文

[全部 4] [正在进行 1] [待接手 1] [阻塞 1] [冲突 1]       [+ 新建任务]

正在进行
实现 GitHub 同步引擎       当前：事件合并与幂等校验       下一步：补跨设备测试
                         最近更新：Claude / Windows · 12 分钟前

待接手
设计事件 Schema            Handoff 已准备             下一步：接受交接
```

### 任务行/卡片字段

- 任务名称
- 当前状态和当前关注点
- 下一步摘要
- 最后更新时间
- 阻塞、待接手或冲突标记
- Agent/设备辅助信息（仅在有活动或异常时显示）

卡片不展示长篇上下文；点击进入详情后，必须能看到任务接续主文档中的关键信息。

## 4.2 任务详情：接续主视图

任务详情的首屏不是单一进度百分比，而是一个可直接交给下一位 Agent 的恢复摘要：

```text
任务：实现 GitHub 同步                         [进行中] [同步]
目标：让 Mac 上的任务状态可在 Windows + Claude Code 恢复

当前状态
事件 schema 已确定，正在实现 pull -> validate -> rebuild 流程

最近完成                         下一步
✓ 定义 event_id 和父事件          实现 sync 流程并补跨设备测试
✓ 增加重复事件幂等校验            [认领] [记录 checkpoint]

关键决策
GitHub 事件历史是事实来源；Markdown 是给人和 Agent 的投影

问题与阻塞
Windows 换行符导致 JSONL 校验失败，需统一 LF

验证结果
2026-09-02 · pnpm test -- sync · 12/12 通过

相关上下文
src/sync.ts · tests/sync.test.ts · 分支 feature/sync

最近更新：Codex / MacBook Pro · 未同步事件 2
```

必须支持折叠查看：`目标与验收`、`最近工作`、`决策`、`问题与失败尝试`、`文件与命令`、`验证结果`。用户未定义阶段时隐藏阶段栏，不显示虚假的“2/5”。

### 关键交互

- 点击卡片进入任务详情
- 点击“新建任务”打开内联创建面板
- 点击同步状态查看本地/远程差异
- 拖拽不是首轮必需，状态变更使用明确操作菜单

## 5. 新建任务面板

### 入口

- 项目任务列表右上角 `[+ 新建任务]`
- Agent 对话提出“建议创建任务”后打开同一面板

### 字段

- 任务名称
- 项目
- 目标
- 验收标准
- 初始阶段（可添加 3 到 7 个阶段）
- 默认 Agent/设备（可留空）

### 确认行为

提交按钮文案：`创建并同步任务`。

提交后显示确认摘要：

```text
将创建任务「Agent Task Sync」
4 个阶段 · 当前 Agent：Codex · 设备：MacBook Pro
[确认创建] [返回编辑]
```

默认不因普通聊天自动创建任务；自动识别只能生成建议，必须确认。

## 6. 任务详情页的辅助内容

### 页面目标

本节补充 4.2 的接续主视图，定义次级标签和操作；任务详情的首屏仍以接续摘要为主。

### 顶部区域

```text
Agent Task Sync                         [同步] [更多]
实现多 Agent、多设备任务同步
In Progress · Phase 2/5 · Claude / Windows
下一步：确定事件 Schema 并写入测试
```

顶部必须优先呈现目标、当前状态和下一步，不把活动流放在最上方。

### 主内容区

#### Overview 标签

- 目标和验收标准
- 阶段列表和完成度
- 当前负责人、设备和会话
- 阻塞项
- 关联仓库、分支、commit、PR
- 最近 checkpoint

#### Timeline 标签

- 按时间倒序显示事件
- 每条事件显示 Agent、设备、事件类型、摘要和关联文件
- 支持筛选 `progress`、`phase_completed`、`blocked`、`handoff`

#### Handoff 标签

- 已完成工作
- 未完成工作
- 关键决策
- 已知错误
- 下一步
- 测试结果
- `[创建 Handoff]`、`[接受 Handoff]`

#### Sync & Conflicts 标签

- 本地未同步事件
- 最后 pull/push 时间
- 远程领先/本地领先状态
- 冲突双方和冲突原因
- `[同步]`、`[查看差异]`、`[标记为已处理]`

## 7. Agent 对话侧面板

这是原型必须模拟的第二个入口，验证产品不是孤立的项目页面。

### 恢复状态

```text
已恢复任务：Agent Task Sync
当前阶段：数据模型设计（2/5）
上一位 Agent：Codex / MacBook Pro
已完成：竞品分析、PRD、同步协议草案
下一步：定义 task/event/handoff Schema
本地未同步：2 条事件

[继续工作] [先同步] [查看 Handoff]
```

### Checkpoint 建议

```text
我检测到“PRD 阶段”可能已经完成。
建议记录 checkpoint：完成 PRD，下一步进入数据模型设计。

[确认记录] [修改摘要] [忽略]
```

### 冲突提示

```text
检测到 Windows 上的 Claude 和 Mac 上的 Codex 都更新了 Phase 2。
没有自动覆盖任何内容。

[查看冲突] [继续只读模式]
```

## 8. Handoff 创建流程

```text
点击“创建 Handoff”
  -> 自动填充当前任务接续摘要
  -> Agent 补充决策、错误和下一步
  -> 完整性检查
  -> 用户确认
  -> 任务进入 Handoff Ready
  -> 写入事件并同步
```

### 完整性检查

- 当前阶段明确（如果任务使用阶段；未定义时不阻止交接）
- 下一步只有一个主要动作
- 最近测试结果存在
- 未提交文件有说明
- 阻塞项已标记是否需要人工决策

## 9. 同步流程

### 正常同步

```text
点击同步
  -> 拉取 GitHub
  -> 读取新增事件
  -> 合并并重建 task_plan.md 和项目概览
  -> 显示差异
  -> 提交本地事件和接续文档
  -> 推送 GitHub
  -> 显示已同步
```

### 同步状态

- 已同步：本地和远程一致
- 本地领先：有待推送事件
- 远程领先：需要先 pull
- 合并中：正在重建状态
- 冲突：需要人工查看
- 离线：事件保存在本地，显示待同步数量

## 10. 原型数据

预置两个项目和四个任务；默认先展示项目列表，再进入 Agent Task Sync：

| 任务 | 状态 | Agent/设备 | 用途 |
|---|---|---|---|
| 完成竞品分析 | Completed | Codex/Mac | 正常完成 |
| 实现 GitHub 同步 | In Progress | Claude/Windows | 主路径 |
| 设计事件 Schema | Handoff Ready | Codex/Mac | 交接路径 |
| 解决并行状态冲突 | Needs Review | Codex + Claude | 冲突路径 |

## 11. 必须可点击的原型路径

### 路径 A：从项目列表继续任务

```text
项目列表 -> 进入 Agent Task Sync -> 点击“实现 GitHub 同步” -> 查看下一步 -> 点击“继续工作”
```

### 路径 B：Agent 创建任务

```text
Agent 面板 -> 建议创建任务 -> 确认摘要 -> 创建并同步 -> 新任务详情
```

### 路径 C：跨设备 handoff

```text
项目列表 -> 项目任务列表 -> 任务详情 -> Handoff -> 创建 -> 模拟 Windows/Claude 接受 -> 状态变为 In Progress
```

### 路径 D：冲突处理

```text
同步状态 -> 冲突 -> 查看双方事件 -> 选择保留/合并 -> 生成修正事件
```

## 12. 状态和边界

原型必须设计这些状态，而非只画成功路径：

- 空项目：显示创建任务和从 Agent 导入的入口
- 无任务：显示清晰的下一步行动
- 离线：保留本地操作并显示待同步数量
- 同步失败：显示原因和重试
- Agent 未绑定：允许人类继续操作，但提示未绑定执行者
- Handoff 不完整：指出缺失字段，不允许直接提交
- 冲突：不显示“自动解决成功”，除非有明确事件依据
- 无权限：显示只读状态和申请访问入口

## 13. 推荐原型工具

以下工具按本项目需求排序，价格和免费额度以 2026-09-02 官方页面为准，使用前应再次确认。

| 工具 | 适合做什么 | 免费情况 | 推荐度 |
|---|---|---|---|
| [Penpot](https://penpot.app/) | 完整 UI、组件、协作原型 | 开源；官方云有免费方案，也可自托管 | 首选，适合长期沉淀 |
| [Figma Starter](https://www.figma.com/pricing/) | 高保真界面和交互原型 | 有免费 Starter，但文件、协作和 AI 能力有限 | 首选，生态最好 |
| [Excalidraw](https://excalidraw.com/) | 用户流程、信息架构、低保真线框 | 免费、开源、无需登录即可开始 | 先画流程首选 |
| [tldraw](https://www.tldraw.com/) | 白板式流程和可交互草图 | 有免费在线编辑；协作能力视方案变化 | 适合快速共创 |
| [v0](https://v0.dev/) | 直接生成 React/Web UI 草稿 | 有免费额度，但按 credits 计费且会变化 | 适合从原型进入代码 |
| [Uizard](https://uizard.io/) | 文本/草图到界面原型 | 有免费计划，但项目和 AI 生成次数有限 | 适合非设计师快速试错 |
| [Lovable](https://lovable.dev/) | 从描述生成可运行 Web 应用 | 有免费额度，但按使用量限制 | 适合验证可运行交互，不是纯原型首选 |

### 推荐组合

```text
Excalidraw：先画信息架构和四条用户路径
  -> Figma 或 Penpot：画中保真可点击原型
  -> v0：把已确认的任务详情页转成 React 骨架
```

如果优先开源和自托管，使用：

```text
Excalidraw + Penpot
```

如果优先速度和社区模板，使用：

```text
Excalidraw + Figma Starter + v0
```

## 14. 原型验收标准

- 新用户能在 30 秒内找到当前进行中的任务
- 任务详情首屏能看懂目标、当前状态、下一步和最近验证结果
- 不打开原始对话也能完成一次 handoff
- 模拟切换到另一台设备后，用户能从 `task_plan.md` 恢复工作
- 同步冲突不会被隐藏，用户能看到双方变化
- Agent 面板和 Web 页面呈现同一份任务状态
- 空、离线、失败、冲突和只读状态都有明确反馈
- 原型中没有把完整聊天 transcript 作为默认同步内容
