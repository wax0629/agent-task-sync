# 状态接续与 Agent 适配

## 状态最小集合

跨会话接续至少能恢复：任务目标和验收、当前焦点、最近完成、下一步、关键决策、未解决问题、失败尝试、相关文件、提交/未提交变化、验证结果、当前责任和同步状态。字段不是为了填表，而是为了让下一 Agent 可以判断“现在是什么、做过什么、接下来做什么、为什么这样做”。

## 事实与投影

- 结构化事件或其他追加式事实源保留历史、写入者、时间和因果/版本关系。
- `progress`、`task`、`plan`、`handoff` 等可读文档可以由事实源重建；手工修改会被覆盖时，必须在文档中明确。
- 同步冲突保留双方事实，进入人工审阅；不能以最后写入静默覆盖另一分支。
- 共享载体可以是 Git 状态分支、文件协议或其他明确授权的存储；不要默认需要数据库或常驻服务。

## Handoff 流程

```text
当前 Agent 读取状态
  -> 写 checkpoint（当前事实）
  -> 生成 handoff 候选
  -> 用户/授权方确认
  -> 同步共同载体
  -> 下一 Agent sync/read context
  -> 检查完整性并接受 handoff
  -> 继续工作并回写 checkpoint
```

未确认的 checkpoint/handoff 只能作为候选，不能产生持久写入。下一 Agent 不应重新创建同一任务；先根据稳定 ID 恢复并明确接受。

## 适配器边界

适配器只负责把平台生命周期（session start、压缩前、停止、handoff 等）转换为统一调用；状态模型、Reducer、同步和安全确认由共享核心负责。适配器应：

- 使用稳定的 stdin/stdout 或平台契约，不把用户文本拼进 shell 命令。
- 输出可解析结果，明确 `continue`/warning/confirmation 状态。
- 未确认不调用写入；CLI 失败时不阻断主 Agent 会话。
- 复用同一 Skill 和 CLI/协议，不为每个平台复制一套任务逻辑。

## 跨设备验收

至少跑通：A 端创建/更新 -> 同步共同 remote -> B 端恢复并接受 -> B 端写入 -> A 端回读。除功能结果外，还要记录 OS、Shell、路径（含空格/反斜杠）、凭据方式、版本、代码 checkout 是否保持不变和 Hook 的真实输出。等价双 clone 测试只能证明协议/逻辑，不能替代实体设备结论。
