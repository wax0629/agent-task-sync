# 可复用模板与门禁

## Proposal / FullSpec

```markdown
# [设计点标题]

## 动机 / 用户故事
## 目标用户
## 现有做法及不足
## 本期范围
- 做：
- 不做：
## 关键决策与依据
### 备选方案
### 最终选择与放弃理由
## 基本概念与信息结构
## 原型 / Demo
## 验收标准
- 现状：
- 提议后的行为：
- 边界 / 非法情况：
```

门禁：真实场景和目标用户清楚；范围、备选、选择理由和信息结构完整；有界面产品已有原型；验收可执行。小改动可以使用 MiniSpec，但不能省略影响范围和验收。

## 架构澄清

```markdown
## 产品基线
## 模块与职责
## 关键数据模型
## 接口契约与模块调用
## 对既有逻辑的影响
## 技术风险与验证方式
## 任务拆分
## 架构演进说明
```

门禁：空骨架可编译；接口真实；主干已串联；风险在编码前暴露；没有用目录或技术栈清单代替架构。

## 实现 Issue

```markdown
# [具体、可验证的任务标题]
## 背景
## 目标
## 范围
- 包含：
- 不包含：
## 设计 / 接口影响
## 验收标准
- [ ]
## 对应 Milestone / Proposal
```

## PR

```markdown
## 关联 Issue
Implements #123

## 改动内容
## 设计说明
## 范围核对
- [ ] 只包含 Issue 范围
- [ ] 无无关重构/生成物
## 验证
- `command`: passed
## 风险与回滚
## AI 使用说明
- 关键 Prompt：
- 人工 Review：
- 维护责任：
```

发布前必须核对实际 diff 与 Issue 全量匹配；候选不明确、部分匹配、无匹配或混入多个无关目标时暂停拆分，不硬关联。

## 验收记录

至少记录：环境/版本、目标、步骤、预期、实际、证据链接、失败与重试、未覆盖边界、结论。明确区分自动化、等价环境、实体设备、真实 Agent 生命周期和真实用户试用。
